## 파일 하나로 배포 (IPFS·USB·첨부)

`index.html` 만 옮기면 스크립트를 못 찾아 **백지**가 된다. 하나로 합쳐서 쓰면 된다.

```bash
node build-standalone.js            # dist/한월공략소.html (0.3MB, 지도 없음)
node build-standalone.js --full     # dist/한월공략소-전체.html (487MB, 지도 원본 화질·공략까지 전부)
node build-standalone.js --full --levels 3,4,5,6   # 같은 것을 70MB로 (확대하면 흐림)
node test-standalone.js             # 단독 실행 검증
node test-browser.js                # 진짜 크롬으로 열어 지도·이미지 확인 (playwright 필요)
```

`--full` 은 지도 타일(배율 0~6 전부)·자생지 색칠·높이 데이터·공략 이미지까지 파일 하나에 넣는다.
`--levels` 로 담을 배율을 줄여 가볍게, `--no-guides` 로 공략 이미지를 뺄 수 있다.

- **가벼운 판**(지도 없음): 지도 탭에 안내와 웹 지도 링크가 뜨고, 공략 이미지는 인터넷에서 불러온다
- **전체판**: 외부 파일 0개. 487MB라 USB·클라우드로 옮기는 게 편하다 (여는 데 약 3초)
- 사이트로 올릴 때는 폴더째 올리는 쪽이 낫다 (DEPLOY.md)

## 버전 보관

버전을 올릴 때마다 스냅샷을 남긴다.

```bash
node snapshot.js                      # index.html의 APP_VERSION으로 versions/v2.0.0/ 생성
node snapshot.js --note "무엇을 바꿨는지"
node snapshot.js --list               # 저장된 버전 목록
node snapshot.js --force              # 같은 버전 덮어쓰기
```

- 담기는 것: `index.html`·데이터·스크립트·테스트·문서·`map/index.html` (버전당 약 1MB)
- 빠지는 것: 지도 타일 321MB, 공략 이미지, 자생지 색칠, 높이 데이터 — 명령 한 줄로 다시 만들 수 있어서
- 되돌릴 때는 그 폴더 내용을 제작 폴더에 덮어쓰면 된다
- `node test-core.js` 를 돌리면 현재 버전 스냅샷이 없을 때 알려준다

- 설정은 브라우저에 자동 저장. 기기를 옮길 땐 상단 **내보내기 / 불러오기**(JSON)

## 성능

- **지연 렌더** — 보고 있는 탭만 그린다. 입력 반응 420ms → **7ms**, DOM 노드 12,500 → **650**
- **위치 탭 분할 렌더** — 검색·필터 시 필요한 덩어리만 (118ms → **6ms**)
- **저장 디바운스** — `localStorage` 기록은 250ms에 1회, 창 닫을 때 즉시 (`window.flushSave()`)
- **무거운 건 필요할 때만** — 지도 타일은 보이는 것만, 높이 데이터 2.6MB는 지도를 만질 때,
  자생지 색칠은 켤 때, 공략 이미지는 열 때
- 첫 로딩: 계산기 약 300KB(gzip ~80KB), 지도 약 370KB

## 기능

- **목표 역산** — 곡괭이 1~5성 · **낫 1~5성** · 화로 아이템 · **NPC 제작 69종**
  (명인대장장이 15 + 목걸이 조각 합성 3 · 조수 4 · **조선장 배장비 16 + 주작단** ·
  무림맹주 3 · 대장장이 일반 제작 9 · **서고관리인 비급 18**)를
  목표로 넣으면 광산 재료까지 전부 역산. 연쇄 제작(한철단조석 ← 접합제 ← 송진칠료,
  5성외륜 ← 4성외륜 ← … ← 1성외륜)도 자동
- **상점 구매가 합산** — 1성 배장비(각 5,000전)·상점 비급(월섬검법·단섬검법 각 5,000전)처럼
  상점에서 사야 하는 재료는 상점가를 표시하고 총 비용에 포함
- **직접 구할 재료 분리** — 화로·광산으로 못 만드는 재료는 따로 모아 항아리 좌표·필요 도구까지 표시
- **실패 확률 반영** — 기대 시도 횟수, 실패로 날아가는 재료·하위 도구(곡괭이·낫)까지 계산
- **시간 계산** — 화력(0.99^수치)·화로시간감소·**대장장이 VIP** 반영(전부 곱연산), 직렬 / 슬롯 병렬 / 최단(의존 관계 한계) 3종
- **제작 순서 체크리스트** — 재료 → 화로 → NPC 제작 순서대로, 체크 상태 저장됨
- **전개도** — 레시피 트리 펼치기/접기
- **확률 시뮬레이션** — 몬테카를로로 비용 p10/p50/p90/최악 + 재료 소요 분포 + 히스토그램
- **레시피 도감** — 검색, 광산 재료별 사용처 역인덱스
- **셋 단위 표기** — 64개 = 1셋. 필요량을 `89셋 4개`로 표시 (셋 크기 변경 가능, 끌 수도 있음)
- **업데이트 내역** — 상단 버튼, 새 버전이면 빨간 점 표시
- **광산** — 광산 65곳 좌표·색깔별 산출·추천 순회 동선. **부족한 재료가 어느 색 광산 몇 번에서 나오는지** 계산 결과와 연결
- **NPC·영단·비급** — 제작 NPC 좌표와 요구 재료, 명인대장장이 제작 15종(회당 1,000전, 성공 1개당 기대비용),
  대장장이 조수(강화·능력이전·귀속해제·제작), **조선장 배장비**(1성 상점 5,000전 · 2~5성 70/60/50/40%),
  **무림맹주**(토벌패·시공단·무림맹비급), **서고관리인**(비급 상점 2종 · 제작 18종),
  **대장장이 일반 제작 9종**(목걸이 계열은 실패 시 조각 → 명인대장장이가 조각 3개로 복구),
  **비급 27종** 획득처·제작 재료, 영단 19종 획득처
- **장비 제작** — 50~180제 방어구/무기 재료·제작서 수량, 제작대 티어 확률, 장신구 옵션. **재료를 목표에 바로 추가**
- **확률·부적** — 잠재/추가능력, 토벌의뢰, 우물던전, 무기외형상자, 부적 **189종 6등급**(신화 포함) 확률,
  신화 옵션 표, 부적표↔확률시트 불일치 표.
  **리롤 계산기**로 1회 확률 / n회 안에 1번 이상 / 평균 소요 / 90%·99% 도달 횟수 계산
- **위치·웨이포인트** — 사냥터 20곳, 약초 자생지 19종 38곳(**자생지별 색**), 적환단·해태단·기린단 단서,
  탐색 항아리 12곳, 의문의 상자 41곳, **동상 3곳·비석 17곳**. 단서마다 **공략 이미지 보기**(28건)
- **약초 조합 계산기** — 약초 3~5개를 고르면 등급 점수 합계(A1·B2·C3·S4)로 결과 환 표시
- **홈(메인 화면)** — 열면 먼저 뜨는 첫 화면. 숫자 요약(광산·웨이포인트·부적·업데이트),
  바로가기 카드 8개, 최근 업데이트 3건, 쓰는 요령. 홈에서는 사이드가 숨어 넓게 보인다
- **통합검색** — 상단 검색창(`Ctrl+K`)에서 재료·NPC·사냥터·약초·부적·웨이포인트까지 한 번에 검색.
  `↑`·`↓` 로 고르면 **미리보기**(분류·설명·좌표)가 뜨고, 거기서 **탭에서 보기 / 지도에서 보기**.

- **웨이포인트 편집기** — 앱에서 추가·수정·삭제·숨김. 가져온 웨이포인트도 **원본은 그대로 두고 표시만** 덮어씀

## 원문 해석 (앱 안 "원문 해석 메모"에도 표시)

2026-08-09 수정된 메모 기준. 레시피·비용·시간은 원문 그대로 반영됨.

- `일반제작성공률증가` = 원래 확률 ×1.1 (70%→77%, 5%→5.5%)
- `화력` = 1당 화로 시간 1% 곱연산 감소 → `0.99^화력`, 최대 50에서 약 -39.5%
- `일반제작비용 -10%`는 대장장이 제작비에만 적용 (1성곡괭이 상점 구매가 제외)
- `대장장이 VIP` = 화로 대기시간 -10%, 화력·화로시간감소와 **곱연산**

이 해석이 실제 게임과 다르면 `craft-core.js`의 해당 값만 고치면 됨.

## 웨이포인트 출처 분리 (지도 연동 대비)

좌표 데이터는 **출처가 절대 섞이지 않도록** 분리되어 있음. `game-data.js`:

| origin | 무엇 | 원본이 어디 |
|---|---|---|
| `webmap` | 광산 65 + 제작 NPC 10 + 스폰 1 + 지도 위치 215 = **291** | **이 파일**. 웹맵에서 가져온 것이라 여기서 고침 |
| `map` | Xaero 지도 웨이포인트 361 (세트 38종) | **지도 프로젝트**. 여기선 주입만 받고 저장 안 함 |

> 지도 광산 66곳 vs 웹맵 광산 65곳처럼 **개수부터 다르다**. 절대 합치지 말 것.

### 지도 연동 (폴더 통합)

지도 뷰어가 **`map/` 안에 같이 들어있다**. 이 폴더 하나만 있으면 계산기·지도가 전부 돈다.
경로가 상대경로(`map/index.html`)라 **폴더째 옮기거나 다른 PC로 복사해도 링크가 안 깨진다**.

```
제작/
  index.html          계산기 (더블클릭)
  map/index.html      지도 뷰어
  map/tiles/          지도 타일 321MB
  map-waypoints.js    지도에서 뽑은 웨이포인트 (자동 생성)
```

지도를 다시 빌드했으면 새 `out/` 내용을 `map/`에 덮어쓰고 아래를 한 번 돌린다:

```bash
node import-map-waypoints.js                  # map/ → 옆 폴더 지도 순으로 자동 탐색
node import-map-waypoints.js "D:/…/index.html"
node import-map-waypoints.js --with-death     # 사망 지점 포함 (기본 제외)
node import-map-waypoints.js --all-dims       # 모든 차원 (기본 overworld만)
```

`map/`이 프로젝트 안이면 링크를 **상대경로로 저장**하고, 밖이면 절대경로로 저장하면서 경고한다.
`map-waypoints.js`가 없으면 "아직 연결 안 됨"으로 뜨고 나머지는 그대로 동작한다.

**🗺️ 지도 탭**에서 계산기 안 지도를 바로 본다. x/z 이동, 스폰 이동, 높이 4단계, 새 탭 열기.
상태바 좌표는 **X → Y → Z 순서**이고 **커서 y**가 같이 뜬다 (`map/heights.js`가 있을 때. 8블록 평균이라 `≈` 근사값이고,
웨이포인트 위에 올리면 정확한 y가 나온다).

**큰 창으로 열기 ⛶** 는 지금 보던 좌표 그대로 화면 90% 크기 새 창을 띄우고,
**전체화면** 은 지도 프레임만 전체화면으로 만든다.

### 약초 자생지 색칠

웹맵과 같은 자생지 이미지(7300×7300 투명 PNG)를 지도 위에 겹쳐 그린다.
좌표 변환은 웹맵 `map-logic.js`의 배율(0.445733 / 0.445873)과 영점(3650.73 / 3647.71)을 그대로 썼다.

```bash
node download-overlays.js        # 19종 → map/overlays/ + map/overlays.js (약 5MB)
```

지도에서 **`Y`키**(툴바 `약초`) → 약초별로 켜고 끈다. 켠 목록은 저장된다.
자생지 **점 웨이포인트**(약초별 색)도 그대로 있으니 취향대로 쓰면 된다.

### 지도 커서 y (높이 데이터)

지도 타일은 그림이라 높이를 모른다. 원본 프로젝트(`D:/백업/한월/제로소 지도`)의 Xaero 리전 파일에는
블록마다 `height`가 있으므로, 거기서 8블록 간격으로 표본을 뽑아 쓴다.

```bash
python build-heightmap.py            # 리전 1,024개 → map/heights.js (약 6분, 3.6MB)
python build-heightmap.py --step 4   # 더 촘촘 (용량 4배)
python build-heightmap.py --stats    # 통계만
node test-heights.js                 # 광산·사냥터·약초 좌표와 오차 대조
```

검증 결과: 광산 65곳 오차 **중앙값 1블록**, 사냥터 2블록, 약초 10블록.
NPC는 실내·지하(예: 고대의제작대 y=-13)가 섞여 있어 차이가 크다 — 정상이다.
표의 `지도` 버튼을 누르면 지도 탭이 그 좌표로 이동하고, `↗`는 새 탭으로 연다
(딥링크 `#world/dim/map/layer/x/z/scale`). 탭을 열기 전에는 지도를 불러오지 않는다.

광산 탭에서는 지도 웨이포인트를 세트별로 걸러 보고 이름·좌표로 검색할 수 있다.
목록은 **`목록 표시` 체크박스로 접었다 펼 수 있고**, 각 행의 `관련` 버튼은 대응하는 탭으로 넘어간다
(광산→광산, 적환단·기린단·해태단→영단, NPC→NPC, 화로→레시피).

### 웹맵 좌표를 지도에 웨이포인트로

```bash
node inject-map-waypoints.js            # 광산 65 + NPC 10 + 스폰 1 + 지도 위치 215 = 291개 주입
node inject-map-waypoints.js --remove   # 주입한 것만 다시 빼기

node inject-my-waypoints.js             # 앱에서 내보낸 my-waypoints.json → [내] 세트로 주입
node inject-my-waypoints.js --remove    # [내] 주입분만 빼기
```

지도 안에서 **`W`키** → 세트를 골라 켜고 끄고, 목록의 **체크박스로 하나씩** 켜고 끈다
(`전부 켜기` / `전부 끄기`는 지금 목록에 보이는 것만 대상, 꺼둔 건 브라우저에 저장됨).
**`O`키(설정)** → `지도 위 웨이포인트`로 전부 끄고, `기본값으로`를 누르면 꺼둔 것도 복구된다.
주입분은 세트 이름이 **`[웹맵] `** 으로 시작한다 — 색깔별로 나뉘어 있어 따로 껐다 켤 수 있다.

| 세트 | 개수 |
|---|---|
| `[웹맵] 녹색광산` / `청색광산` / `황색광산` / `적색광산` | 24 / 14 / 12 / 15 |
| `[웹맵] 제작 NPC` | 10 |
| `[웹맵] 스폰` | 1 |
| `[웹맵] 사냥터` | 20 |
| `[웹맵] 약초 <약초 이름>` (19종) | 38 |
| `[웹맵] 적환단` / `해태단` / `기린단` (+ 단서별 하위 세트) | 19 / 28 / 37 |
| `[웹맵] 항아리` | 12 |
| `[웹맵] 의문의 상자` | 41 |
| `[웹맵] 동상` / `비석` | 3 / 17 |

- **여러 번 돌려도 안전하다** — 주입분(`wp.webmap`)을 매번 싹 걷어내고 다시 넣는다
- **지도에서 직접 찍은 웨이포인트 368개는 건드리지 않는다**
- 지도를 새로 빌드해 `map/`을 덮어썼으면 이 명령을 다시 돌리면 된다

```js
GameData.setMapWaypoints([{ name:'내 집', x:100, y:70, z:-200, kind:'거점' }]);
GameData.waypoints('webmap');   // 가져온 것만
GameData.waypoints('map');      // 지도 것만
GameData.waypoints();           // 둘 다 (각 항목에 origin 태그가 붙어 구분됨)
GameData.waypointCounts();      // { webmap: 291, map: 368 }
```

- `setMapWaypoints()`는 **교체**(누적 아님), 좌표가 숫자가 아니면 무시, `y` 없으면 0
- `waypoints()`는 **사본**을 돌려주므로 결과를 고쳐도 원본이 오염되지 않음
- 광산 탭 "웨이포인트 출처" 표에서 출처별 개수와 지도 웨이포인트 목록을 따로 확인 가능

출처 목록은 `game-data.js`의 `SOURCES`에 모아 뒀고, 앱 **요약 탭 하단 "데이터 출처"** 표와 상단 링크 버튼으로도 볼 수 있음.
대장장이 조수(강화·능력이전·귀속해제·제작)는 인게임에서 직접 확인해 넣은 값.
게임이 업데이트되면 `game-data.js`만 고치면 됨 — `node test-core.js`가 매핑 누락·확률 합계를 자동으로 잡아줌.

> **부적 확률 규칙**: 종류당 확률 = `100 ÷ 그 등급 종류 수`. 고지된 등급 전부 이 값과 일치하므로,
> 확률 시트에 없는 **신화 등급도 같은 규칙으로 `100 ÷ 13 = 7.6923%`** 로 산출했음.
> 단, 시트의 확률은 *등급 안에서 어떤 부적이 나오나*(리롤용)이고 **등급 자체가 뜰 확률은 어느 등급도 미고지**다.
>
> 부적표(최신)와 확률 시트 사이에 불일치 5건이 있어 목록은 부적표 기준으로 넣었고,
> 차이는 앱 부적 탭의 "부적표 ↔ 확률 시트 불일치" 표와 `game-data.js`의 `TALISMAN_DIFF`에 기록해 뒀음.

> 장비 티어 표기(`5T`~`1T`)는 확률 시트의 "제작창 왼쪽 상단부터 오른쪽으로 5·4·3·2·1티어" 설명을
> 웹맵의 장비 나열 순서에 그대로 대응시킨 것. 실제 제작창 배치와 다르면 `game-data.js`의 `SMITH_GEAR.items` 순서만 바꾸면 됨.
